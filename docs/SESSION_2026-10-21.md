## 3. สิ่งที่แก้ในโค้ด

### 3.1 `src/train.py`: gradient accumulation สำหรับ GPU เล็ก
- เพิ่ม argument `--micro_batch N`: ทุก batch ถูกแบ่งเป็นชิ้นละ ~N ตัวอย่างและสะสม gradient ก่อนอัปเดต จึง **effective batch, lr และ scheduler เท่าเดิม** ไม่ต้องแก้ hyperparameter ใน `methods.py`
- ค่าเริ่มต้น `None` = อัตโนมัติ (`resolve_micro_batch`): ใช้ 8 เมื่อ GPU มี VRAM < 8 GB **และโมเดลเป็น `ProposedNet`** (proposed กับ ablation ทั้ง 11 ตัว) ส่วนคู่เทียบไม่แบ่ง เพราะใช้ batch ต้นฉบับได้อยู่แล้ว และไม่ควรไปเปลี่ยนพฤติกรรม BatchNorm ของมัน
- `--micro_batch 0` = ปิด
- augmentation (SpecAugment, mixup) ทำกับทั้ง batch ก่อนแบ่ง และแบ่งด้วย `np.array_split` ให้ชิ้นขนาดใกล้กัน กันไม่ให้ BatchNorm เจอชิ้นที่มี 1 ตัวอย่าง
- batch ตอน eval เปลี่ยนเป็น `(micro_batch หรือ batch) × 2`
- บันทึกคอลัมน์ `micro_batch` เพิ่มใน `results.csv`
- **ข้อต่างจากการรันบนการ์ดใหญ่ (ต้องเขียนในรายงาน):** BatchNorm (bn0 ของ ConvNeXt AudioSet และใน AuxCNN) คำนวณสถิติทีละ 8 ตัวอย่างแทน 16 และ weighted CE ที่ถ่วงต่อชิ้นแล้วนำมารวมกัน ไม่เท่ากับการคำนวณทั้ง batch แบบเป๊ะ (ต่างกันน้อยมาก)

## 4. การตรวจสอบที่ทำแล้ว (ผ่านทั้งหมด)

**VRAM ที่วัดได้ (forward+backward, AMP, input ICBHI 8 วินาที):**

| โมเดล | batch | peak VRAM |
|---|---|---|
| ConvNeXt (proposed / abl_imagenet) | 16 | 4.0–4.4 GB (เกินการ์ด) |
| ConvNeXt | 8 | 2.2–2.4 GB |
| DenseNet201 | 16 | 2.28 GB |
| Park Inception | 32 | 2.23 GB |
| VGG16 / MobileNetV2 / Wanasinghe / Dongre | 32 | ≤ 1.24 GB |

**ผลทดสอบ:**
- `prepare_data --dataset icbhi`: 6,898 รอบ จาก 920 ไฟล์ 126 ผู้ป่วย, train 4,142 / test 2,756 ✅ (val 872 แยกจาก train ตามผู้ป่วย)
- checkpoint AudioSet: โหลดครบ 185/185 tensor ค่าตรงทุกตัว stem เป็น conv 4×4 padding (4,0) ตรงกับ `after_stem_dim=[252, 56]` ที่ upstream ใช้กับ checkpoint 471mAP (`third_party/.../evaluate_convnext_on_audioset.py`) ไม่ใช่ค่าเริ่มต้น `[56]`
- ทดสอบว่า forward เหมือนต้นฉบับ: ป้อนไฟล์ตัวอย่างของ upstream ผ่าน frontend แบบต้นฉบับ (32 kHz, n_fft 1024, hop 320, mel 224 bins, 50–14000 Hz) + head 527 คลาส ได้ top-3 เป็น Music 0.84, Ukulele 0.70, Speech 0.63 ตรงกับ label จริง (Speech; Music; Ukulele)
- ทั้ง 18 วิธีบน ICBHI จริง (1 epoch, `--limit 128`) รันจบทุกวิธี น้ำหนัก ImageNet ของ timm ดาวน์โหลดได้
- KAUH และ HF_Lung ด้วยข้อมูลจำลอง (`scripts/make_dummy_data.py`): parse ชื่อไฟล์และ label, group 5-fold และการฝึก 3 แบบโมเดลบน CPU ผ่านหมด หลังทดสอบลบ `splits/*_group5fold.csv` และ cache ของข้อมูลจำลองออกแล้ว (โฟลเดอร์ `datasets_dummy/` ยังอยู่ ลบได้)
- `stats.py` ทดสอบด้วย CSV สังเคราะห์ 6 seeds × 3 dataset: ค่า Wilcoxon p = 1/64, Holm, Friedman χ² = 9 และ Nemenyi CD = 2.708 ตรงกับที่คำนวณมือ
- `demo_report.py` สร้าง HTML ได้ และ resume ของ `run_experiments` ตรวจรันที่เสร็จแล้วได้ถูก
- ผลทดสอบทั้งหมดเก็บไว้นอกโปรเจกต์ (scratchpad) ไม่ปนกับ `results/`

**การตีความ (ระวัง: 5 epoch และ seed เดียว ใช้ดูแนวโน้มเท่านั้น ห้ามสรุปว่าวิธีไหนดีกว่า):**
- proposed ชนะคู่เทียบทั้ง 6 วิธี แต่ห่าง DenseNet201 แค่ ~1 คะแนน
- ablation ที่ชี้ว่าเทคนิคนั้นช่วย (ตัดออกแล้วแย่ลง): AudioSet pretrain (ไม่ pretrain −11.7, ImageNet −7.8), SE gating (concat −6.9), log-Mel ดีกว่า PCEN (−4.4), band-pass (−1.6), SpecAugment (−0.9)
- **ablation 5 ตัวได้คะแนนสูงกว่า proposed:** Mel อย่างเดียว (+1.7), ไม่มี Δ (+2.6), ไม่ใช้ class weight (+2.7), ไม่ใช้ drop path (+3.3), ไม่ใช้ mixup (+3.6) แปลว่าที่ 5 epoch ยังไม่เห็นว่า ΔMFCC และ regularization ช่วย สมมติฐาน (ยังไม่ได้พิสูจน์) คือ mixup และ drop path ต้องเทรนนานกว่านี้ถึงจะเห็นผล
- หลายวิธียังไม่ converge: `shakya_vgg16` ใช้ lr 1e-6 ตามเปเปอร์จึงแทบไม่ได้เรียนรู้ใน 5 epoch และ Sp ของ proposed ยังต่ำ (41%)
- เทียบได้กับตัวเลขจากเปเปอร์ (ไม่ได้รันเอง): BTS (Interspeech 2024) ICBHI score 63.54%

3. ถ้าจะปรับ lr: `--plan tune` ก่อน แล้วรัน `--plan main --use_tuned`
4. RQ3 (`--plan cross`) ต้องดาวน์โหลด KAUH และ HF_Lung_V1 ก่อน แล้วรัน `prepare_data` เช็กไฟล์ที่ถูกข้าม และเช็ก `parse_kauh_sound` / `hf_group` กับชื่อไฟล์จริง
