## 3. เทียบกับงานก่อนหน้า: เราประเมินคนละแบบ

| งาน | ICBHI score (official split) |
|---|---|
| CNN6/CNN14, SCL (Moummad & Farrugia) | 53.9–58.0 (README ใน `third_party/2_lung_ICBHI/scl_icbhi2017`) |
| **ของเรา proposed seed 0** | **57.80** |
| Patch-Mix CL (Bae et al., Interspeech 2023) | 62.37 (README ใน `third_party/2_lung_ICBHI/patch-mix_contrastive_learning`) |
| BTS (Interspeech 2024) | 63.54 (จากเปเปอร์ ไม่ได้รันเอง) |

**ข้อค้นพบจากการอ่านโค้ดใน third_party:** ทั้ง Patch-Mix และ SCL ใช้ **test set เป็น validation สำหรับเลือก epoch ที่ดีที่สุด**
- Patch-Mix: `val_dataset = ICBHIDataset(train_flag=False, ...)` แล้วเก็บ best ตามคะแนนชุดนี้ (`main.py` บรรทัด 215, 459)
- SCL: `val_ds = ICBHI(..., split='test', ...)` (`main.py` บรรทัด 72)

ของเราเลือก epoch จาก val ที่แยกผู้ป่วย 20% ออกจาก train แล้วเปิด test ครั้งเดียวตาม RD_v2 จึงเข้มกว่า และได้ข้อมูลฝึกน้อยกว่า (3,270 กับ 4,142 รอบ) ตัวเลข SOTA จึงเทียบตรงๆ ไม่ได้ ซึ่งน่าจะได้เปรียบกว่าเราพอสมควร แต่ยังไม่ได้วัดว่าเท่าไร

ข้อสรุปเรื่องการวางตำแหน่งงาน:
- contribution หลักตาม RD_v2 คือการเทียบอย่างยุติธรรมแบบแยกผู้ป่วยกับคู่เทียบ 6 งานบน protocol เดียวกัน ส่วนนี้แนวโน้มดี (demo: proposed ชนะทั้ง 6 วิธี แต่ห่าง DenseNet201 แค่ 1 คะแนน) แต่ต้องรอผลหลาย seed
- การชนะตัวเลข SOTA 62–64 ตรงๆ ตอนนี้ยังไม่เห็นแนวโน้ม และไม่ควรอ้างจากตัวเลขที่ต่าง protocol
- ทางเลือก (ยังไม่ได้ทำ ต้องถามอาจารย์ก่อน): รายงานตัวเลขเสริมแบบ "เลือก epoch จาก test เหมือนงานก่อนหน้า" แยกไว้อีกตาราง พร้อมระบุชัดว่าได้เปรียบ เพื่อเทียบกับวรรณกรรมเท่านั้น

## 4. การตั้งค่า Mel ปัจจุบัน (`src/features.py`, `src/models.py`)

| ขั้น | ค่า |
|---|---|
| เตรียมเสียง | 16 kHz → band-pass 120–1800 Hz (Butterworth order 5) ทั้งไฟล์ → normalize ด้วย peak → ตัดรอบหายใจ → repeat-pad เป็น 8 วินาที |
| STFT | n_fft 2048, win 400 (25 ms), hop 160 (10 ms), Hann, center + reflect, power |
| Mel | 128 bands, 50–2000 Hz, librosa ค่าเริ่มต้น (Slaney) |
| Log | 10·log10(max(p, 1e-10)) ไม่มี ref และไม่มี top_db |
| ขนาด | 128 × 801 |
| Normalize | mean/std ต่อ channel จากชุด train |
| Augment (train) | SpecAugment ปิดความถี่ 2 แถบ ≤15% + เวลา 2 แถบ ≤10%, mixup α 0.2 |
| เข้า ConvNeXt | transpose เป็น [T, F] → bilinear interpolate F จาก 128 เป็น 224 → bn0 |

เทียบตอน pretrain (Pellegrini, AudioSet): 32 kHz, win 1024 / hop 320, **Mel 224 bins ช่วง 50–14,000 Hz** ส่วนของเราใช้ 50–2,000 Hz แล้วยืดเป็น 224 bins จึงยืดแกนความถี่ราว 7 เท่าจากที่ checkpoint เคยเห็น

จุดสังเกต (ยังไม่ได้ทดลอง):
1. ช่วง 1800–2000 Hz แทบว่าง เพราะ band-pass ตัดไปแล้ว (ราว 7% ของภาพ)
2. ความละเอียดความถี่จริงอยู่ราว 40 Hz (window 25 ms) Mel bins ล่างๆ จึงแคบกว่านั้นและซ้ำกันบ้าง
3. ความต่างกับ pretrain อาจเป็นสาเหตุหนึ่งที่ยังห่าง SOTA ถ้าจะทดสอบ ทำได้เป็น ablation เพิ่ม เช่น Mel 224 bins 50–8000 Hz ไม่ interpolate และไม่ทำ band-pass แต่ช่วง 50–2000 Hz และ band-pass ระบุไว้ใน RD_v2 จึงต้องคุยกับอาจารย์ก่อน

## 6. เรื่องที่รอตัดสินใจ

1. **กติกา early stopping:** จะไม่เลือกโมเดลจาก epoch ในช่วง warmup (หรือเริ่มนับ patience หลังจบ warmup) โดยใช้กับทุกวิธีเท่ากันหรือไม่ ถ้าเปลี่ยน ควรรัน proposed และ abl_mel_only ใหม่ ข้อเสนอของ Claude Code คือให้เปลี่ยน แต่ยังไม่ได้แก้โค้ด
2. **รัน PoC ที่เหลือ:** แผน poc ยังเหลือ 16 จาก 18 รัน (6 วิธี × seeds 0–2) บนเครื่องนี้ ConvNeXt ใช้ ~25–60 นาทีต่อรัน คู่เทียบเร็วกว่านั้นมาก ควรตัดสินใจข้อ 1 ก่อน
3. จะรายงานตัวเลขเสริมแบบเลือก epoch จาก test เพื่อเทียบกับวรรณกรรมหรือไม่ (ต้องถามอาจารย์)
4. จะทดลอง ablation ช่วงความถี่ Mel ให้ใกล้ตอน pretrain หรือไม่ (เปลี่ยนจาก RD_v2 ต้องถามอาจารย์)
5. ควร commit การแก้ทั้งหมดเข้า git หรือไม่ (ยังไม่ได้ commit)
